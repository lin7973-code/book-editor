<!-- block:ch02-sec01-h001 -->
## 웹페이지는 여러 역할이 합쳐져 만들어진다

<!-- block:ch02-sec01-p001 -->
브라우저에서 보는 웹페이지는 하나의 화면처럼 보인다. 하지만 안쪽에서는 화면의 구조, 디자인, 동작을 서로 다른 파일이 맡을 수 있다. 처음부터 복잡한 원리를 모두 알 필요는 없다. 세 가지 역할만 구분해도 첫 웹페이지를 이해하는 데 충분하다.

<!-- block:ch02-sec01-p002 -->
HTML은 제목, 입력창, 버튼처럼 화면에 무엇이 있는지를 정한다. CSS는 글자 크기, 색, 간격처럼 어떻게 보일지를 정한다. JavaScript는 버튼을 눌렀을 때 메모를 추가하는 것처럼 사용자의 행동에 반응한다. 세 이름이 낯설다면 각각 구조, 모양, 동작이라고 기억해도 된다.

<!-- block:ch02-sec01-e001 -->
> 예를 들어 “추가” 버튼 하나를 생각해보자. HTML이 버튼을 화면에 놓고, CSS가 버튼의 크기와 모양을 꾸미며, JavaScript가 버튼을 눌렀을 때 실제로 메모를 목록에 넣는다.

<!-- block:ch02-sec01-h002 -->
## 브라우저는 파일을 읽어서 화면을 만든다

<!-- block:ch02-sec01-p003 -->
`index.html` 파일을 브라우저로 열면 브라우저는 먼저 HTML을 읽는다. HTML 안에 CSS와 JavaScript 파일을 연결하는 내용이 있으면 그 파일도 찾아서 함께 읽는다. 그래서 세 파일의 위치나 이름이 바뀌면 디자인이나 버튼 동작이 사라질 수 있다.

<!-- block:ch02-sec01-p004 -->
파일이 어디에 있는지를 나타내는 방법을 경로라고 부른다. `style.css`라고 적혀 있다면 보통 현재 HTML 파일을 기준으로 같은 폴더에서 그 파일을 찾겠다는 뜻이다. 경로라는 말이 어렵다면 “브라우저가 파일을 찾아가는 주소”라고 생각하면 된다.

<!-- block:ch02-sec01-e002 -->
> 직접 확인해보기: 세 파일이 같은 폴더에 있는 상태에서 페이지를 열어본다. 그다음 `style.css`의 이름만 잠시 `style-old.css`로 바꿔 새로고침해보자. 디자인이 사라진다면 HTML이 원래 이름의 CSS 파일을 찾지 못한 것이다. 확인이 끝나면 파일 이름을 되돌린다.

<!-- block:ch02-sec01-h003 -->
## 클릭도 브라우저가 알아차리는 하나의 사건이다

<!-- block:ch02-sec01-p005 -->
버튼 클릭이나 글 입력처럼 사용자가 한 행동을 개발에서는 이벤트(event)라고 부른다. 이름은 낯설지만 뜻은 단순하다. “어떤 일이 일어났다”는 신호다. JavaScript는 특정 이벤트가 생겼을 때 무엇을 할지 정할 수 있다.

<!-- block:ch02-sec01-p006 -->
따라서 버튼이 화면에 보인다고 기능까지 완성된 것은 아니다. 버튼의 모양은 있어도 클릭했을 때 실행할 JavaScript가 연결되지 않았다면 아무 일도 일어나지 않는다. 화면이 이상하면 구조와 디자인을 보고, 클릭이 안 되면 동작 부분을 보는 식으로 문제를 나눌 수 있다.

<!-- block:ch02-sec01-h004 -->
## 인터넷 웹사이트는 다른 컴퓨터에서 파일을 받아온다

<!-- block:ch02-sec01-p007 -->
내 컴퓨터의 파일을 직접 여는 것과 인터넷 주소로 접속하는 것은 다르다. 인터넷에서는 브라우저가 웹사이트를 제공하는 쪽에 필요한 내용을 요청하고, 그쪽에서 파일이나 데이터를 돌려준다. 이때 웹사이트를 제공하는 컴퓨터나 실행 환경을 서버(server)라고 부른다.

<!-- block:ch02-sec01-p008 -->
주소를 입력하고 화면이 나타나는 짧은 순간에도 요청과 응답이 오간다. 이 기본 흐름만 이해해두면 뒤에서 배우는 배포와 데이터베이스가 훨씬 자연스럽다. 배포는 다른 사람이 접속할 수 있는 곳에 웹사이트를 올리는 일이고, 데이터베이스는 서비스가 기억해야 할 정보를 보관하는 곳이다.
